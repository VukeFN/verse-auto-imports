**Optimize Imports No Longer Imports the Same Path Twice**: organizing a file that contains both an import anchored by a comment marker (one whose line opens a `<#` or `<#>` comment over the lines below it) and a second, live import of the same path now leaves one import of it. Previously the live one was hoisted into the rebuilt block anyway, leaving the file importing the path twice - once at the top and once at the anchored line. A comment written above or trailing the dropped duplicate is dropped with it, since it annotates a statement that no longer exists. The duplicate is only dropped in a file whose every module import is an absolute `/Path`: the anchored line ends up below the rebuilt block, and any other kind of import may be resolving its own first segment against the copy being removed - a dotted `using { Economy.Shop }` needs the `using { Features }` that brings `Economy` into scope to sit above it. A file holding a bare or dotted import anywhere, including inside a module body, keeps the duplicate, which is legal Verse rather than a compile error.
