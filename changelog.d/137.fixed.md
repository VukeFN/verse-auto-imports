**Clearing the Project Path Cache No Longer Breaks an Update in Flight**: the declaration cache survives being cleared while it is re-parsing saved `.verse` files. Saving a file schedules a re-parse 500 ms later, and three things clear the cache while that runs — the **Clear Project Path Cache** command, UEFN rewriting the `.uefnproject`, and extension shutdown. The re-parse then wrote its result into a cache that was no longer there and failed with a `TypeError` nothing caught, losing the update and leaving the pre-edit declarations in workspace storage for the next session to load as current. The update is now abandoned cleanly when the cache it was computed against has been cleared or rebuilt, and a failed re-parse is logged instead of escaping as an unhandled rejection
